# DBFS2 → Alien（rvfs 0.2.0）适配：源码级函数级验证报告

> 本文件是「零 Alien 修改」方案的落基验证。所有签名均来自真实源码抽取（非凭 API 名字猜测）。
> 源码位置：`/tmp/proj_check/{Alien-main,dbfs2-main}/`，新版 VFS：`/tmp/rvfs_new/vfscore/src/`。
> 配套代码：`dbfs2-adapter/` crate（Step 1 骨架 + 已验证的转换函数）。

---

## 0. 结论速览（先看这里）

1. **两套 rvfs 不兼容**：DBFS2 依赖 `Godones/rvfs`（旧 API：`Inode`/`FileSystemType`…），Alien 用 `os-module/rvfs`（新 API：`VfsInode`/`VfsFsType`…）。二者同名包，构建图冲突。
2. **薄适配可行的根因**：DBFS2 的 `dbfs_common_*` 后端函数只吃 `usize` inode 号 + `&[u8]` 缓冲 + 标量参数，**与 rvfs 类型无关**，因此 adapter 可 1:1 转发，JammDB 完全不动。
3. **但「看起来 1:1、编译不过」的 7 个风险点全部真实存在**（见 §4），外加 2 个方案原未列出的**构建级阻塞**（见 §5）。
4. **严格 0 改 Alien 不可行**，实际是：**Alien 3 处微小改动 + DBFS2 3 处微小改动 + 新建 adapter crate**；全部适配逻辑在 adapter/DBFS2 侧。

## ④ 7 个风险点的源码级结论

1. **create/mkdir inode 生命周期**：新 VFS 用 `Arc<dyn VfsInode>` 且目录走 `create(..Dir..)`。适配：`DbfsInode{ino:usize}` 极轻量，每次 `lookup`/`create`/返回都 `Arc::new` 一个新实例即可，**无需全局 registry**（risk7 一并解决）。`mkdir` = `create` 带 `VfsNodeType::Dir`。
2. **VfsInode ↔ VfsDentry 互相持有**：`DbfsInode` 只存 `ino`；`DbfsDentry` 存 `name` + `ino` + `parent: Weak<dyn VfsDentry>`。`dentry.inode()` 现造 `DbfsInode`；`inode` 不反向持有 dentry（避免环，用 Weak 即可）。
3. **readdir cursor 语义**（最易崩）：DBFS2 `dbfs_common_readdir` 内部用 `GLOBAL_READDIR_TABLE` 且 `assert!(offset==save_offset+1)`、`assert!(val.is_some())`——是给 FUSE「多次 offset 递增」设计的。新 VFS 是「每次返回一个 `Option<VfsDirEntry>`，按 `start_index` 索引」。**适配：首次（`start_index==0`）调用一次 `dbfs_common_readdir(ino,&mut vec,0,false)` 把整目录拉进本地缓存（静态 `Mutex<BTreeMap<usize,Vec<VfsDirEntry>>>`），之后按 `start_index` 取 `vec[start_index]`，越界返回 `None`。绝不再二次喂它 offset**，绕开其内部 assert。
4. **get_attr 字段映射**：`st_mode = attr.perm as u32`（DBFS2 的 `perm` 已含 S_IFDIR 等类型位，见 common.rs:161，故 1:1 直赋即得正确 mode）；`st_ino=ino as u64`；`st_size=size as u64`；`st_blocks=blocks as u64`；`st_nlink/nlink`；`st_uid/uid`；`st_gid/gid`；`st_rdev=rdev as u64`；`st_blksize=blksize`；`st_atime/mtime/ctime` 由 `DbfsTimeSpec{nsec:u32}` → `VfsTimeSpec{nsec:u64}`；`st_dev/__pad/__pad2/unused=0`。
5. **VfsError 枚举成员**：DBFS2→VfsError 映射：`PermissionDenied(1)→PermissionDenied` · `NotFound(2)→NoEntry` · `AccessError(13)→Access` · `FileExists(17)→EExist` · `InvalidArgument(22)→Invalid` · `NoSpace(28)→NoSpace` · `NameTooLong(36)→NameTooLong` · `NoSys(38)→NoSys` · `NotEmpty(39)→NotEmpty` · `Io(5)→IoError`。**缺口（VfsError 无对应成员，需裁断）**：`NoData(61)→IoError` · `RangeError(34)→Invalid` · `NotSupported(95)→NoSys` · `Other(999)→IoError`。
6. **VfsSuperBlock 创建/root inode**：`mount` 调 `dbfs_common_root_inode(0,0,ct)` 拿 root ino（幂等，首次会建根），构造 `DbfsSuperBlock{root_ino, fs:Arc<dyn VfsFsType>}` 存进静态 `Once`，再包 root `DbfsDentry{name:"/", ino:root_ino}`。`stat_fs()`：`DbfsFsStat→VfsFsStat` 逐字段（f_type 用 `f_fsid as i64`；f_fsid=`[f_fsid as i32,0]`；f_namelen=`f_namemax as isize`；f_frsize=`f_frsize as isize`；f_flags=`f_flag as isize`；f_spare=`[0;4]`）。
7. **usize inode 号 → Arc<dyn VfsInode> 绑定**：`DbfsInode{ino:usize}` 即绑定。`Arc::new(DbfsInode{ino})` 作为 `Arc<dyn VfsInode>` 返回。`create`/`lookup`/`link` 从 `DbfsAttr.ino` 构新实例。`rename_to` 的 `new_parent: Arc<dyn VfsInode>` 经 `downcast`/`ino` 字段取 `new_parent.ino`（给 `DbfsInode` 加 `pub fn ino(&self)->usize`）。

> 新 VFS 缺 `open`：Alien 的 `KernelFile::new(dentry,flag)`（basic.rs:100）不调 fs open，故 `dbfs_common_open` 在 S2 可不用（权限检查可后置）。

## ⑤ 方案原未列出的 2 个构建级阻塞（必须处理）

**A. `dbfs_common_*` 在私有模块，外部调不到。**
DBFS2 `lib.rs` 是 `mod file; mod inode; mod link; mod fs_type; mod attr;`（无 `pub`），故 `dbfs2::dbfs_common_create` 等**外部不可见**。`clone_db()` 也是私有（但 adapter 不需它，函数内部已用）。
→ **DBFS2 改动**：在 `lib.rs` 增加定向 `pub use`（避免与既有 `pub use fs_type::DBFS` 重名）：
```rust
pub use common::{DbfsAttr, DbfsDirEntry, DbfsError, DbfsFileType, DbfsFsStat, DbfsFileType as _, DbfsPermission, DbfsResult, DbfsTimeSpec};
pub use file::{dbfs_common_open, dbfs_common_read, dbfs_common_readdir, dbfs_common_write};
pub use fs_type::{dbfs_common_root_inode, dbfs_common_statfs, dbfs_common_umount};
pub use inode::{dbfs_common_access, dbfs_common_create, dbfs_common_link, dbfs_common_lookup, dbfs_common_attr, dbfs_common_rename, dbfs_common_rmdir, dbfs_common_truncate};
pub use link::{dbfs_common_readlink, dbfs_common_unlink};
```

**B. `rvfs` 包名冲突。**
DBFS2 `Cargo.toml:9` `rvfs = { git = "Godones/rvfs" }` 与 Alien 的 `vfscore = { package="rvfs", git="os-module/rvfs" }` **包名都是 `rvfs`**，同构建图必冲突。
→ **DBFS2 改动**：把依赖改名为 `rvfs_old`，并改 `common.rs` 两处 `use`：
```toml
rvfs_old = { package = "rvfs", git = "https://github.com/Godones/rvfs.git" }
```
```rust
// common.rs:10
use rvfs_old::dentry::DirentType;
// common.rs:441 (impl_rvfs mod)
use rvfs_old::{inode::InodeMode, superblock::StatFs};
```
adapter 侧：`vfscore = { package="rvfs", git="os-module/rvfs" }`（即新 VFS）。三者包名互不撞：`rvfs`(os-module) / `rvfs_old`(Godones) / `vfscore`(本地别名，包名仍 rvfs 但仅 adapter 用，与 Alien 的 vfscore 同源)。

**C.（前置风险，S2 才暴露）JammDB 存储后端。**
`init_dbfs(db: jammdb::DB)` 需要 `jammdb::DB`。`jammdb::DB::open` 走 std 文件系统，内核内无。需在 Alien 侧提供 **no_std 兼容的 DB 构造**（内存盘/anon 后端，或复用 initrd 块）。adapter `mount` 里以 `TODO(DB-BACKEND)` 占位，S2 联调时确定。这是唯一「真正要动点内核存储」的地方。
